# 安心看：需求讨论记录

## 项目定位

应用名称已确定为：**安心看**。

“安心看”是一款面向老年人的 Android App，重点解决看不清锁屏信息、不会操作复杂界面，以及不方便输入文字的问题。

当前产品副标题仍暂定为：**大字时间与语音助手**。该副标题不作为第一阶段界面或验收条件。

## 已提出的需求

### 1. 锁屏后显示大字信息

老年人在手机锁屏后，需要在屏幕点亮时看清：

- 时间；
- 日期；
- 星期几。

当前 Android 手机在未解锁时显示的星期和其他时间信息通常较小，因此 App 需要提供更大的字体和更清晰的布局。

需要注意：普通 Android App 不一定能稳定替换系统锁屏界面。实际产品需要验证 `setShowWhenLocked`、`setTurnScreenOn`、通知、后台启动限制，以及不同 Android 版本和手机厂商的行为。

产品路径分为：

- 主路径：系统允许时，在锁屏上显示大字时间、日期和星期；
- 降级路径：系统不允许自动显示时，通过锁屏通知让用户点击进入大字页面。

### 2. 天气查询与播报

2026-10-04 用户明确进入下一阶段：在现有大字时钟页面上增加天气，不再等待荣耀现场验收后才开始。拨号仍不做。

已确定：

- 日期、时间、星期和天气放在同一个页面，不增加第二个页面。
- 打开 App 时在同一次请求里申请 `ACCESS_FINE_LOCATION` 和 `ACCESS_COARSE_LOCATION`。只有授予精确位置才调用 `GPS_PROVIDER`；只授予大致位置或拒绝时，不把结果当作 GPS 坐标，日期、时间和星期仍然立即显示。
- 播报内容只包含天气状况和气温，不播报湿度、空气质量、风力或体感温度。天气状况使用短词，例如晴、多云、阴、雨、雪，不只分成“下雨 / 不下雨”。
- 语音开头包含日期、时间和星期，再接天气。例如：“今天是 2026 年 10 月 5 日星期一 14 点 35 分，晴，气温 15 到 20 度。星期二，小雨，气温 18 到 21 度。”
- 这一版先实现定位和网络都可用时的核心路径。无网络、定位失败的详细提示以后再处理，但这些失败不能挡住时钟三行。

这台红米 `23013RK75C` 尚未实际朗读。小米系统可以配置文字转语音引擎，但不能据此认为中文语音数据已经安装。

### 3. 语音查询和语音播报

用户可以通过语音查询天气或其他后续支持的信息，App 通过语音播报结果。

第一版暂定采用“按键说话”：

1. 用户点击麦克风按钮；
2. App 开始录音；
3. 用户说出问题；
4. App 完成语音识别；
5. 系统或后端处理问题；
6. App 显示文字结果并进行语音播报。

第一版暂不做持续监听和唤醒词。

`SpeechRecognizer` 不等于离线识别。正式实现前必须确定：

- 使用 Android 系统识别服务还是指定供应商；
- 音频是否上传；
- 上传到哪家供应商以及哪个地区；
- 音频和文字是否保存；
- 保存多久；
- 是否支持用户关闭联网语音识别；
- 无网络时如何处理。

### 4. 语音拨打预存电话

对于不识字或不方便操作通讯录的老年人，App 应支持通过语音拨打预存联系人。

用户可以使用联系人姓名或称呼，例如：

- 女儿；
- 闺女；
- 孩子。

联系人和电话号码第一版默认保存在手机本地，不上传后端。

基本流程：

1. 用户说出拨号请求；
2. 语音识别得到文字；
3. 大语言模型识别联系人意图；
4. App 在本地联系人中匹配联系人；
5. App 语音确认联系人和拨号动作；
6. 用户确认后打开系统拨号界面；
7. 用户在系统拨号界面确认拨出。

第一版使用 Android `ACTION_DIAL`，不申请 `CALL_PHONE` 直接拨号权限。

MVP 必须满足：

- 没有匹配到唯一联系人时，不打开拨号界面；
- 匹配到联系人后，必须先确认；
- 用户拒绝或没有确认时，不拨号；
- 通过 `ACTION_DIAL` 打开系统拨号界面；
- 不申请 `CALL_PHONE` 权限。

### 5. 接入大语言模型

语音查询和语音拨号需要接入大语言模型，主要用于：

- 理解自然语言天气问题；
- 识别联系人称呼；
- 理解不同说法表达的同一意图；
- 识别天气查询、拨号请求和未知请求；
- 对不清楚的请求进行追问。

大语言模型不直接执行拨号，也不直接操作手机。模型只返回经过约束的结构化意图，Android App 再执行确定性逻辑。

例如：

```json
{
  "intent": "call_contact",
  "contactName": "女儿",
  "needsConfirmation": true
}
```

允许的意图集合第一版可以限制为：

```text
weather_query
call_contact
unknown
```

## 用户和使用环境

目标用户是老年人，特别是存在以下困难的用户：

- 看不清小字体；
- 不认识或不方便输入文字；
- 不熟悉复杂的手机操作；
- 不方便在通讯录中查找联系人。

因此界面需要优先考虑：

- 大字体；
- 高对比度；
- 少量操作步骤；
- 明确的语音反馈；
- 拨号前确认；
- 权限状态清楚可见；
- 网络不可用时给出容易理解的提示。

## 分发和部署边界

App 可以不上架华为、小米、荣耀等应用商店，通过 APK 安装包分发。

但安装来源不是 App 备案的判断条件，不上架应用商店不构成自动豁免。正式提供或面向测试用户提供天气、语音和大语言模型等在线服务时，需要按规则先办理 App 备案。

纯离线锁屏原型可以先用于开发和设备验证。纯封闭开发测试是否落入具体备案边界，官方条文没有明确豁免，需要向所在地通信管理部门或腾讯云取得书面答复。

后端计划部署到腾讯云或其他云服务器。服务器迁移时，App 使用固定域名，不把服务器 IP 写死在 APK 中。

## 分阶段范围

### 第一阶段：离线锁屏原型 APK

先生成一个可通过 APK 安装到真实手机的纯离线版本，完成核心大字页面和锁屏能力验证，再交给亲人在实际手机上试用。根据实际使用反馈，重新确认天气、语音拨号和其他功能是否值得继续开发。

包含：

- 大字时间；
- 日期；
- 星期；
- 锁屏显示能力验证；
- 点亮屏幕能力验证；
- 可选通知降级路径；
- Android 版本和手机厂商测试；
- 亲人实际试用和反馈记录。

不包含：

- 天气后端；
- 语音识别；
- 大语言模型；
- 云端账号；
- 登录功能。

### 阶段一结束后的决策门槛

2026-10-04 用户决定提前开始天气查询和语音播报，不再等待亲人试用反馈。语音拨号和大语言模型仍不开始。

### 第二阶段：本地联系人和语音拨号

包含：

- 手动添加联系人；
- 联系人别名；
- 语音识别方案验证；
- 语音确认；
- `ACTION_DIAL` 拨号流程；
- 权限和隐私边界确认。

### 第三阶段：天气

这一节的旧结论已经作废。当前天气范围以本文第 2 节为准：同一页面、GPS 自动定位、不做手动输入城市。下面保留旧文字只作历史记录：

- 旧方案是手动选择城市；
- 旧方案把定位和自动城市判断排除在第一版之外。

### 第四阶段：大语言模型

包含：

- 天气自然语言查询；
- 联系人称呼识别；
- 语音命令分类；
- 模糊请求处理；
- 不明确请求追问。

## 当前未决需求

- 锁屏页面是否必须在屏幕点亮后自动出现，还是通知点击进入也可以接受；
- 首批支持哪些 Android 版本和手机品牌；
- 时间页面已确定和天气放在同一页；
- 是否需要用户账号和云端同步；
- 联系人是否永远只保存在本地；
- 语音识别是否接受上传音频；
- 天气播报已确定为天气状况和气温，不包含湿度、空气质量、风力和体感温度；
- 是否需要离线语音识别；
- 是否需要免确认直接拨号；
- 首批测试用户数量和使用地区。
