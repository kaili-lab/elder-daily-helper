# 安心看：第一阶段剩余问题与建议

本文只记录当前尚未最终验证、但会影响第一阶段构建、交付或现场试用的问题。已经确定的产品规则以 `lockscreen-prototype-acceptance.md` 为准。

## 一、第一阶段实现前必须决定

### 1. Android 工程的 `targetSdk`

**当前状态：已确定为 `36`。**

`minSdk` 保持 `31`（Android 12），`compileSdk` 和 `targetSdk` 使用 `36`。三者含义不同：`minSdk` 决定最低可安装系统，`compileSdk` 决定编译所用 API，`targetSdk` 决定应用声明适配的 Android 行为版本。

不因为亲人手机的具体型号降低 `targetSdk`；Android 版本和荣耀系统行为仍需在现场验证。

### 2. 应用包名和签名

**当前状态：包名已确定为 `com.anxinkan.app`；release 签名延后。**

包名在首次安装到亲人手机前保持不变。debug 构建可用于本地和临时设备验证，不是正式交付物。release keystore 在需要生成可长期覆盖更新的 APK 前创建，存放在仓库外并完成备份；在保管和备份方案确定前不生成。

包名和签名决定后续 APK 能否覆盖安装。签名用于确认后续 APK 与此前 APK 使用同一签名身份且内容未被替换，不等于第三方认证的开发者实名。


## 二、亲人试用后再决定

### 3. 亲人是否真的能用“星期 1–7”判断礼拜日

**当前状态：现场未验证。**

**建议：**先说明“星期一 = 1，……，星期日 = 7”，再让亲人自己根据“星期 + 数字”判断星期几和是否为礼拜日。记录是否已经接受过这套映射，以及实际判断结果；只有遇到混淆时才记录混淆情况，不把混淆预设为必然发生或验收门槛。

**理由：**“不识字”不等于不能理解数字，但数字映射是否适合他，必须由真实用户验证，不能由开发者代替判断。

### 4. 字号、颜色和排版是否舒适

**当前状态：现场未验证。**

**建议：**先使用当前默认方案：黑色背景、暖白文字、琥珀色星期数字，星期最大、时间其次、日期再次。让亲人至少连续使用一天，记录是否能快速找到星期、是否需要更大字号、是否刺眼或疲劳；这一天是自然日观察，不要求 App 一直停在前台。

**理由：**代码可以保证布局不重叠，但不能替代真实视力和屏幕体验测试。颜色和字号是可调整的实现默认值，不是永久设计结论。

### 5. 锁屏大字是否真的有价值

**当前状态：现场未验证。**

**建议：**分别记录三种使用方式：解锁后打开 App、点亮锁屏后直接看到页面、通过通知点击进入页面。比较亲人实际使用时最容易完成哪一种，不要预先假定锁屏主路径一定比打开 App 更有用。

**理由：**锁屏显示受系统限制，且操作路径可能比“解锁后点击图标”更难理解。真实使用频率比技术上能否实现更重要。

### 6. 通知降级是否值得保留

**当前状态：可选，现场未验证。**

**建议：**只有在锁屏主路径不可用且通知在荣耀锁屏上清晰可辨、点击后无需复杂操作时才保留；通知权限被拒绝或锁屏隐藏内容时，不影响核心功能，也不强行要求用户开启。

**理由：**通知是系统控制较多的增强路径，不能为了“功能完整”增加老人的设置负担。

### 7. 固定钟面图标是否容易找到

**当前状态：已确定做单一大号钟面图标，现场未验证。**

**建议：**在荣耀启动器上观察图标是否容易辨认；如果亲人仍然找不到，优先改图标大小、对比度或桌面位置，不做动态星期图标。

**理由：**图标只负责帮助定位 App，不是显示星期的可靠渠道。动态更新会增加系统兼容性和后台行为问题，当前收益不足。

### 8. 亲人是否需要新功能

**当前状态：天气已经提前开始；拨号和大语言模型仍不做。**

2026-10-04 用户决定先做同一页面上的 GPS 天气和播报文本。语音是否能在红米上朗读，另行实测，不阻塞天气数据功能。

## 三、现场测试顺序建议

1. 记录手机型号、MagicOS 版本、Android 版本、系统字体大小和显示大小。
2. 通过 QQ 接收并安装 `release` APK，记录是否需要允许安装未知应用。
3. 点击图标，确认直接进入大字页面，并由亲人实际辨认“星期 + 数字”。
4. 在默认设置和字体/显示大小调大一级后，检查是否重叠、截断或难以辨认。
5. 修改系统日期、时间或时区，确认页面可见时自动重新计算；如果修改时 App 在后台，回到前台后确认立即重新计算；测试结束后恢复手机原来的日期、时间和时区。
6. 测试熄屏、锁屏点亮、重启后状态恢复和可选通知路径，分别记录结果；不把后台常驻、自动点亮或绕过解锁当作测试目标。
7. 让亲人至少连续使用一天，最好覆盖一次礼拜日前后，记录他主动反馈的问题和主动提出的后续需求。
8. 荣耀现场验收仍未完成，但不阻塞已经决定提前开始的天气功能。

## 四、当前明确不做

- 不做登录、账号、云端同步和多设备支持；
- 不做英文或多语言；
- 不做动态星期图标；
- 不做常驻后台服务、定时轮询或保持亮屏；
- 不做测试开关、调试按钮或模拟日期入口；
- 不做语音拨号和大语言模型。天气已按 2026-10-04 的决定进入开发；中文朗读是否可用另行实测。
