# 安心看：第一阶段锁屏原型验收条件

## 1. 阶段目标

第一阶段是单设备、纯离线原型：不做账号、登录、引导页、云端同步或登录前置条件。

## 2. 版本约束

- 应用名称：安心看。
- 最低支持 Android 版本：Android 12。
- 首要验收设备：亲人实际使用的荣耀手机。该手机的具体型号、MagicOS 版本和 Android 版本待现场测试时记录。
- 其他 Android 版本和手机厂商：作为后续兼容性测试，不代表首要验收设备的结果。
- 本工程 `targetSdk` 固定为 `36`，仍与最低支持版本 `minSdk 31` 分开；不根据亲人手机型号降低 `targetSdk`。

## 2.1 APK 交付与安装

- 第一阶段通过 QQ 发送 APK；亲人在手机上通过 QQ 接收安装包并完成安装。
- 安装过程不要求账号或网络服务；QQ 接收文件本身需要网络，但 App 安装完成后的核心页面不依赖网络。
- 如果 Android 或荣耀系统提示开启“允许安装未知应用”，记录提示和设置路径；这是侧载 APK 的系统安全机制，不算 App 功能失败。
- 安装完成后点击 App 图标，必须直接进入大字页面。
- 卸载后重新安装不作为第一阶段硬性验收条件，只作为开发阶段的额外检查。

## 3. 屏幕方向

- 第一阶段只验收竖屏；横屏不在范围内。
- 打开 App 的页面和锁屏页面都必须保持竖屏。
- 实现时锁定 Activity 方向；现场只验证旋转手机不会导致内容重叠或被截断，不要求提供横屏布局。


## 4. 星期数字规则

星期数字固定使用以下映射：

| 星期 | 数字 |
| --- | ---: |
| 星期一 | 1 |
| 星期二 | 2 |
| 星期三 | 3 |
| 星期四 | 4 |
| 星期五 | 5 |
| 星期六 | 6 |
| 星期日 | 7 |

App 不得使用手机语言、地区设置或系统周起始日设置改变这个映射。

- 第一阶段只提供中文界面，不考虑英文或其他语言；“星期”两个字是固定的语义标识，不随手机系统语言改变。

- 正式交付 APK 不包含测试开关、调试按钮或模拟日期入口；用户只能看到手机系统当前日期、时间和星期。
- 开发阶段单独使用测试覆盖星期映射，至少验证星期一输出 `1`、星期日输出 `7`；不依赖现场临时修改系统日期作为唯一验证。
- 交付给亲人安装的 APK 使用 release 构建变体，不使用 debug 构建变体。

## 5. 必须通过的打开 App 场景

用户点击 App 图标后直接进入大字页面，不显示登录页、引导页、菜单或其他中间页面。

时钟信息本身不依赖网络。天气查询依赖网络和 GPS 定位；打开 App 时申请定位权限。

页面仍直接进入同一个大字页面，不进入第二个页面。日期、时间、星期和天气都放在这个页面上，不遮挡日期、时间和星期。

- 年、月、日；
- 时、分；
- “星期”两个字及按上述规则表示的星期数字，例如“星期 7”，不能只显示单个数字。

首版页面以数字为主，例如：

```text
2026-10-04
14:35
星期 7
```

“星期”是星期数字的语义标识，`7` 是主要视觉内容。同一个页面先显示年月日、时:分和“星期 + 数字”，再显示天气；不进入第二个页面，也不遮挡这三行。打开 App 时可以申请定位权限。普通点击不切换页面。返回键仍按 Android 默认行为处理。

### 可重复判定

- 从点击 App 图标到页面首次显示完整的大字信息，不超过 1 秒；以实际设备从点击动作到肉眼可见为准，必要时用屏幕录制复核。
- 页面显示的日期、小时、分钟和星期数字必须与手机系统当前时间和时区一致；页面可见期间，小时和分钟至少每分钟更新一次；跨过午夜后，日期和星期数字必须自动更新，不要求用户关闭并重新打开 App。息屏后重新点亮、恢复前台或重新打开时，页面必须立即从系统时钟重新计算全部信息，不沿用旧值或等待下一次分钟更新；此规则同时适用于普通页面和系统允许显示的锁屏页面。不显示秒数，也不依赖网络。
- 测试至少覆盖一个星期一和一个星期日，分别确认显示“星期 1”和“星期 7”，避免只验证中间数字。
- 现场测试需先记录亲人是否已熟悉周一为 `1`、周日为 `7` 的映射，以及是否接受过对应关系的教学。由亲人根据完整的星期显示判断当天是星期几、是否为他去教堂做礼拜的日子；照护者可以协助记录，但不能代替亲人的辨认结果。
- 初版视觉基线：屏幕中央显示“星期”两个字和大数字，数字字形高度目标约占屏幕高度的四分之一；“星期”、日期和时间均使用大字体，布局不得重叠或截断。最终是否清晰，以实际设备上的真实用户辨认结果为准。
- App 不阻止系统自动息屏；用户操作时按系统正常行为保持亮屏，无操作时按手机原有的息屏策略熄灭，不额外保持常亮或后台保活。

### 第一版视觉方案（可调整）

- 背景先使用接近黑色 `#0B0B0B`。
- 日期、时间和“星期”文字先使用暖白色 `#FFF4D6`。
- 星期数字先使用琥珀色 `#FFC857`，作为视觉强调；“星期”文字和数字必须同时显示，不能只靠颜色表达星期含义。
- 实现前检查文字与背景的实际对比度，不能使用低对比度的暗黄、橙棕或灰色文字。
- 这些颜色只是第一版试用方案，不是不可修改的硬性验收条件；最终以亲人在实际荣耀手机上的辨认准确性和视觉疲劳反馈为准。
- 页面排版先采用三层纵向布局：中央显示最大的“星期 7”，下方显示次大的 `14:35`，更下方显示较小但清晰的 `2026-10-04`。
- 页面使用纯色背景，不使用渐变、图片、动画或装饰性背景；排版和颜色均属于实现默认值，亲人试用后可以调整。
- 日期区域必须避开荣耀底部手势导航或系统导航安全区；三组内容使用稳定的垂直区域和最小间距，任何情况下都不能重叠、截断或让“星期 7”显示不完整。
- 状态栏和底部导航栏是否隐藏由实现选择，不作为第一阶段验收条件；无论系统栏显示或隐藏，三组信息都必须完整可见，不得被系统栏遮挡或截断。

### 系统字体和显示大小

- 页面文字使用固定视觉字号，不跟随系统“字体大小”缩放。实现可以读取 `fontScale`，但只用于抵消系统字体倍率，不能把它再乘进字号。系统“显示大小”改变屏幕密度，仍需在默认设置下检查三行是否完整。
- 三层布局使用固定字号、稳定垂直区域和最小间距，保证默认系统设置下三行完整、不重叠、不截断。
- 现场测试记录亲人手机的字体大小和显示大小，但不把系统字体调大后的缩放结果作为通过条件。
- 不承诺适配极端字体或显示缩放；系统缩放导致的系统界面变化不作为第一阶段缺陷。

### 日期和时间格式

- 日期固定使用 `年-月-日` 的数字格式，例如 `2026-10-04`。
- 月和日不足两位时补 `0`，例如 `03`、`07`。
- 时间固定使用 24 小时制，例如 `14:35`。
- 小时和分钟不足两位时补 `0`，例如 `08:05`。
- 不显示秒数、上午/下午文字；不跟随手机地区设置改变格式。

## 6. 锁屏显示目标

用户打开大字页面后，使用设备的安全锁定方式锁定手机，再点亮屏幕时，目标是在系统允许的情况下直接看到竖屏大字页面，内容包括：

- 年、月、日，格式如 `2026-10-04`；
- 时、分，使用 24 小时制，格式如 `14:35`；
- “星期”两个字及 `1`–`7` 范围内的星期数字。

需要按以下步骤测试并分别记录结果：

1. 记录设备是否设置了 PIN、图案、密码或其他安全锁；没有安全锁时，标记为“仅熄屏测试”，不能把结果当作完整锁屏验收。
2. 打开 App，确认大字页面显示正确。
3. 等待约 10 秒后按电源键熄灭屏幕；记录熄屏时间。
4. 再按电源键点亮屏幕；在输入 PIN、图案或密码等解锁凭据前，检查是否已经看到大字页面。
5. 如果系统先显示系统锁屏而不是大字页面，记录为锁屏主路径未通过；不得用输入解锁凭据后打开 App 的结果替代。
6. 解锁后再次打开 App，重复一次熄屏、点亮和检查流程，确认屏幕熄灭后再次点亮的结果。
7. 重启手机后，App 只尝试恢复通知或锁屏显示所需的系统注册状态；不要求开机时后台拉起 Activity、自动点亮屏幕或绕过解锁。分别记录：恢复注册是否成功、用户主动点亮后锁屏是否显示大字页面、通知是否可用。
8. 系统或厂商拒绝锁屏显示时，记录通知是否可用；通知属于可选降级路径，不是核心功能通过条件。

该测试不要求 App 在后台自行唤醒屏幕；它验证的是用户主动点亮手机后，在完成解锁前能否看到大字页面。重启后的恢复只针对系统注册状态，不影响解锁后打开 App 的核心验收。

第一阶段不使用常驻后台服务、定时轮询、频繁唤醒或保持亮屏来维持功能。锁屏显示、通知和重启后状态恢复可以使用必要的事件驱动系统机制，例如系统回调或受限的开机广播接收器；这些机制不得在开机时后台拉起 Activity、自动点亮屏幕或绕过解锁。

如果 Android 系统或荣耀系统拒绝应用出现在锁屏上，不把绕过系统限制作为第一阶段要求；必须记录为设备限制。通知仅作为可选降级路径继续验证，通知权限被拒绝不影响解锁后打开 App 的核心功能验收。

## 7. 通知降级路径

当设备不能自动在锁屏上显示大字页面时，可以验证通知降级，但通知不是核心功能通过条件：

- 锁屏上能看到 App 通知，通知使用简短标题，例如“打开安心看”；在该设备的锁屏上验证用户是否能辨认这是进入大字星期页面的入口。
- 用户点击通知后，无需经过复杂菜单或额外设置，直接进入“星期 + 数字”的大字页面。
- 进入页面后显示当前正确的年、月、日、时:分和星期数字；不能显示上次缓存的旧日期或旧星期。
- 通知不能触发拨号、联网或其他未请求的操作。
- 测试时记录通知权限是否授予、锁屏是否隐藏通知内容，以及荣耀系统的电池优化或后台限制。通知权限被拒绝时，记录为通知降级不可用，不影响核心功能验收。

如果系统限制导致锁屏页面和通知都不可用，只要解锁后打开 App 仍能满足核心大字页面验收，第一阶段核心功能仍可通过；锁屏增强能力记录为受系统限制未通过。

## 8. 可选功能

App 固定使用单一的大号钟面图形作为入口图标：高对比、无小字、不组合钟表和日历图形。颜色可沿用页面的黑底、暖白和琥珀色方案；图标只帮助用户定位 App，不显示当前星期，也不作为查看当前星期的可靠渠道。

- 图标在目标荣耀手机的启动器上应能清楚辨认；现场只做可辨认性记录。
- 图标不能替代打开 App 后的“星期 + 数字”大字页面。
- 动态 App 图标属于可选增强功能，不影响第一阶段核心功能通过。

## 9. 首次现场测试记录

测试时记录：

- 手机型号；
- MagicOS 版本；
- Android 版本；
- 屏幕分辨率（如果容易取得）；
- 打开 App 页面结果；
- 锁屏后点亮结果；
- 再次点亮结果；
- 重启后结果；
- 通知降级结果；
- 通知权限状态、锁屏通知内容是否被隐藏，以及荣耀系统电池或后台限制；
- 亲人是否熟悉或接受过 `1`–`7` 星期映射教学，以及是否能根据完整显示辨认当天星期和是否为礼拜日；
- 具体问题和现场照片或屏幕录制。

## 10. 阶段通过标准

第一阶段至少满足以下条件：

1. 通过 QQ 接收的 APK 能在亲人的实际 Android 12 手机上完成安装；如果系统要求允许安装未知应用，记录该系统步骤；
2. 安装后点击 App 图标能直接进入大字页面，不要求账号、网络或运行时权限；
3. 在亲人的实际手机上，解锁后打开 App 能稳定显示正确的年、月、日、时、分和“星期 + 1–7 数字”；
4. 页面首次显示完整内容不超过 1 秒；
5. 亲人在实际手机上能根据“星期”两个字和数字的完整显示判断星期及是否为礼拜日；记录测试前对映射的熟悉程度，不以照护者的辨认代替亲人验收；
6. 锁屏显示结果、重启后的状态注册结果、重启后用户主动点亮的锁屏显示结果和通知降级结果已经分别记录；如果系统限制导致其中任何一项失败，解锁后打开 App 的核心大字页面仍可作为通过依据；通知是否可用、通知权限是否授予，都不影响核心功能通过；如果通知降级可用，还需满足无需复杂操作进入“星期 + 数字”页面；
7. 动态 App 图标不是通过条件。
